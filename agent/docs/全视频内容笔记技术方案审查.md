# 全视频内容笔记技术方案独立审查

日期：2026-11-16。审查对象：[技术方案](全视频内容笔记技术方案.md)。审查角色独立于方案作者。本文为设计审查，不是实现、测试或上线验收。

## 审查范围和依据

- 本次对话PRD：适用于所有视频的独立内容文档，不包含聊天追问；完整覆盖、时间引用、异步恢复、权限及质量验收。
- `agent/AGENTS.md`、开发与维护规范。
- 实际核对 `ContentWork`、`ContentWorkService`、`MysqlContentWorkStore`、`ContentTranscriptionWorker`、`ContentAssetKey`、`ContentReadAuthority`、`ReportArtifacts` 与前端 `answer-renderer.mjs`。
- 以代码存在和方案目标区分当前线上能力；没有执行模型、供应商、数据库集成或生产测试。

## 初审结论

总体方向合理：复用现有持久内容work而非另建队列；文档与聊天解耦；显式全视频范围不扩大原片段解释权限；明确采样分析不等同所有事件无遗漏；采用来源保留、结构化文档与发布门控；UNKNOWN不默认重发；首版不跨账号共享。

初审无P0，发现以下3项P1，需在开工前补齐契约。记录中的“关闭”仅表示设计文字已明确，仍需实现与故障测试证明。

### R1 / P1：Root按用户隔离未下沉到work唯一键

- 位置：方案第4、5节。
- 依据：`MysqlContentWorkStore.enqueue` 的work_key只有asset全字段、stage、segmentId和stageVersion，不含user/root；重复入队返回旧work，保留旧grant。
- 场景：两名用户对同一个公开视频、相同区间和策略生成笔记。若segmentId只编码范围及共同plan摘要，两者绑定同一个work，违反首版按用户隔离，并使重试、授权续期和费用归属相互影响。
- 修复要求：notes segmentId必须包含不可变Root身份、role、范围和输入依赖digest的有界摘要；读取/绑定/ledger/对象提交核对Root归属；单纯Root唯一键包含user不足以解决。恢复代次不改变已有成功原始素材的稳定身份，但下游合成必须随输入变化改变身份。
- 验证：不同用户、同源同策略产生不同work；同一Root重试不会重跑合法成功分片；不能引用其他Root的work或对象。

### R2 / P1：短期grant续期和现有work截止规则冲突

- 位置：方案第6、9节。
- 依据：现有enqueue强制 `deadline <= grant.expiresAt`，worker执行deadline取其最小值；store.requeue只允许FAILED/EXPIRED，没有“有效工作自动续grant”的现成接口。
- 场景：长任务在队列等待到grant接近过期，或处理跨越有效期，仅写“短期可续grant”不能使它恢复；随意更新grant又可能允许旧worker越过新的fence提交。
- 修复要求：明确Root总deadline和单work attempt deadline分别持久化；如何领取前续期、如何对短有效期暂停/重新准入、grant/deadline更新的CAS与fence、权限拒绝与权限服务暂不可用的区别；未知外部调用保留ledger协调。不能把尚不存在的续期能力称为可直接复用。
- 验证：排队中授权过期、运行中撤权、续期前后崩溃、旧worker晚到、同主体续期及不同媒体版本拒绝。

### R3 / P1：Root推进与依赖创建缺少可恢复协议

- 位置：方案第5、6、8节。
- 场景：work入队后、依赖关系绑定前进程崩溃，或两个协调器同时创建下游合成；补齐缺失分片后旧质检/旧合成又尝试发布。仅有Root generation CAS不足以说明这些空窗如何恢复。
- 修复要求：明确扫描协调器和短事务/CAS协议；先持久化完整计划与预期唯一unit，再幂等enqueue并补绑work；下游必须冻结有序输入digest并编码其身份；重试使所有传递依赖变更输入的节点失效；发布事务核对generation、plan、依赖digest、覆盖、质量回执、授权版本和预算。
- 验证：计划提交、enqueue、绑定、合成和发布每个边界注入崩溃，两个协调器并发推进，不出现无主缺口、重复计费或旧内容覆盖新成品。

## 非阻断建议 / P2

- 无对白和画面主导视频应单独形成质量分组，不能用网课成功代替全类型通过。NO_SPEECH应是明确证据状态，不是调用失败或空字符串。
- 超长文档不能一次走现有聊天renderer：它在文本超过64000字符时回退pre，并禁止img。应以受控block独立渲染，分章加载并对单块大小、表格和公式复杂度设上限。
- 补帧后确认的新事实可能改变相邻章节或全局提纲；应由输入digest驱动传递失效，并记录修复次数，避免质检自循环。
- 30分钟、并发1等为建议参数。将30分钟作为首发限制会缩小PRD使用范围，需产品明确决定；没有样本证据前不将其写成已验收能力。
- “全部关键点无重大遗漏”是样本验收门槛，不应作为对未知视频的绝对保证。覆盖manifest证明时间轴按策略被处理，不能证明采样间未发生关键事件。

## 开发与上线门控

设计问题关闭后，可开展技术验证与分批实现；进入上线前仍须完成媒体不可变读取、grant续期、UNKNOWN成本和槽位恢复、权限撤销、完整与部分状态、渲染安全及真实视频评测。当前服务器资源记录仅为此前观察，不构成部署容量证明。12条人工样本是起始基线，不能仅靠总体均分或模型自评宣布所有视频可用。
