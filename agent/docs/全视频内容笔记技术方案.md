# 全视频内容笔记技术方案

日期：2026-11-16；状态更新于2026-11-17。本文保留目标设计，不代表全部已实现。现已实现素材处理、受控生成与检查、发布读取、业务授权和前端入口；宋浩映射课首条线上成品已完成生成、读取、复制、刷新及时间跳转验收，实际边界和证据以[实施记录](全视频内容笔记实施记录.md)为准。分层合成和跨功能素材复用尚未完成，其他类型与时长尚未完成验收。原设计审查见[独立审查](全视频内容笔记技术方案审查.md)。产品依据为本次对话的《EchoFrame 全视频内容笔记 PRD V1.0》。本文未被实测证据替代的参数仍为建议，不是性能承诺。统一架构与约束仍以《Agent架构与工程治理技术设计》和《开发与维护规范》为准。

## 1. 决策摘要与边界

新增显式 FULL_VIDEO_NOTES 业务任务，以整条站内视频为范围生成结构化独立文档。视频页直接创建持久任务，不依赖聊天会话、SSE连接或自由Agent循环持续存活；不新增聊天追问。读者无需选类型，模型依据实际材料规划章节；类型只影响组织，不能改变事实依据。首版登录且可观看视频的普通用户和作者均可用。

采用持久分片生产、章节合成、全片整合、确定性检查、质量检查、原子发布流程。复用现有内容任务的授权、CAS/fence、媒体版本、ASR适配器及私有存储能力；不能直接把现有VideoIndex标记READY当成完整文档。首次发布不跨账号共享结果，不部署OCR/CLIP等重型本地模型。独立后台容量不能侵占前台全部容量。

产品“覆盖完整”仅指按冻结策略成功处理了整个时间轴的所需模态，并完成质量门控；视觉为采样理解，不承诺每帧事件无遗漏。所有可读视频均可看到入口，但超出时长/资源/格式能力时发起前明确拒绝，不能偷偷截取前段。建议首批上限30分钟，与现有宋浩素材对齐；这是待用户确认的首发限制，不是所有视频均已支持的结论。

## 3. 系统流程

```mermaid
flowchart LR
 A[显式生成请求] --> B[实时鉴权/冻结媒体/估算预算]
 B --> C[持久Root与分片清单]
 C --> D[音频及视觉分片]
 D --> E[保留来源的分片事实]
 E --> F[全局提纲/章节合成]
 F --> G[确定性检查及语义质检]
 G --> H[原子发布结构化文档]
 H --> I[实时鉴权后阅读复制]
```

新增业务模块建议`video.notes`，Root协调器只推进确定性DAG；模型负责材料理解和文档组织，不负责决定权限、付费预算、完整状态或发布。显式API任务不需要改AgentRuntime。若以后从聊天启动，只注册业务Task/CompletionOwner，仍经过既有完成裁决及Delivery，不增加另一套聊天终态。

## 4. 输入、接口与幂等契约

建议路由`/api/agent/videos/{videoId}/notes`：POST创建；GET获取当前任务/成品；`POST /{jobId}/retry`补齐可重试缺口；GET `/{jobId}`查状态；GET `/{jobId}/document`读取成品；GET复制用结构化文本。每次使用IdentityPort重新解析登录并由业务权威核对视频。前端只提交sourceVersion和幂等键，不提交媒体URL、授权域、用户ID或范围。范围由后端明确设为[0,durationMs)。

POST返回202及jobId、status、durationMs、sourceVersion、stage、completedUnits/totalUnits、pollAfterMs；拒绝返回DURATION_LIMIT、CAPACITY_EXCEEDED、VIDEO_VERSION_CHANGED等稳定业务码及可读文案。不用模型token比例推算全程进度。客户端关闭不取消后台任务。首版不提供后台取消按钮；撤权/过期始终停止。GET轮询须限频、退避并支持ETag，刷新不创建任务。

唯一键包含tenant、user、ContentAssetKey全字段、输出语言、schemaVersion、analysisPolicyVersion、generationVersion。生成策略版本冻结后不可就地更改。客户端Idempotency-Key在tenant/user内唯一，绑定请求digest；相同键不同请求返回409。并发POST通过数据库唯一约束返回同一Root，不能仅用synchronized。READY再次打开直接读；FAILED重试沿同Root递增retryGeneration，成功子任务仍复用，旧fence结果不得提交。

隔离贯彻到子work：现有work_key没有user字段，因此notes的segmentId必须包含不可变rootId摘要、role、真实范围及inputDigest摘要（编码后遵守128字符上限），不能只用视频范围。root本身已绑定user；dependency唯一绑定root/work，worker及对象/ledger读取复验root归属。同用户相同Root重试可复用成功work，不同用户绝不复用旧grant/work。失败重试计划代次与内容依赖digest一起验证，不能仅凭segmentId相似复用。

## 5. 持久模型与迁移

复用`agent_content_work`作为各阶段work权威，不再建设第二套租约队列。新增SQL编号由实施时扫描现有迁移分配（V31在工作区，不能假定V32空闲）。现有Stage枚举可用，stageVersion隔离worker能力，segmentId必须编码真实范围/计划摘要，避免现有work_key未包含start/end导致冲突。

| 表（建议） | 必要字段/约束 |
|---|---|
| `agent_video_notes_job` | job_id、root_key唯一、tenant/user、asset_json、duration_ms、language、policy_snapshot/digest、status、phase、generation、deadline、budget_reserved/used、plan_digest、active_document_id、error_code、created/updated；状态CAS版本 |
| `agent_video_notes_binding` | tenant/user/idempotency_key唯一、request_digest、job_id；源权限绑定，不存bearer |
| `agent_video_notes_dependency` | root_id/plan_generation/unit_key唯一；work_id、role、owned_range、dependency_ranges、input_digests、required_modalities；工作清单冻结后不可悄悄减少 |
| `agent_video_notes_call` | work_id/attempt/operation_key唯一、dispatch_state、reservation、provider_request_id、result_ref/digest、started/ended、unknown_reason；模型请求指纹与策略版本 |
| `agent_video_notes_document` | document_id、root_id/generation唯一、schemaVersion、body_ref/digest、coverage_manifest_ref/digest、quality_receipt、source_version、status、created；私有不可变对象 |

关系/状态/预算MySQL权威，私有JSON/证据/截图使用既有对象存储基础能力；Redis、Trace和浏览器均非权威。发布事务以Root generation CAS校验，设置唯一active_document及READY，绑定完成校验回执。对象先写后提交；事务失败留下不可访问的孤儿对象，由延迟GC核对所有引用后清理。复制直接根据已发布文档确定性渲染，不能再调用模型。

Root推进协议：有界扫描器扫描QUEUED/RUNNING/PARTIAL中ready_at已到的Root，每次只作数据库短事务推进，不执行模型。以root CAS版本冻结plan/planDigest及依赖意图；数据库事务内写可重放dependency intent，再调用幂等enqueue并CAS绑定workId。若enqueue成功但绑定前崩溃，恢复用相同root-scoped Unit重复enqueue取得同work，禁止新生成随机segmentId。并发推进者只有一个CAS成功；其余重读。下游unit身份必须含有序完整inputDigest列表和节点策略digest，所有前置结果可验证后才发布意图。补片改变digest时，递归失效传递依赖的章节/概览/检查节点，不复用旧质量回执。发布事务校验root状态/generation/planDigest、完整依赖manifestDigest、授权epoch、输出digest和绑定这些输入的qualityReceipt，任一变化均拒绝。发布前额外实时复验业务源版本/权限；该外部检查与本地事务不构成跨库原子撤权，访问时始终重新验证epoch以阻止旧版本消费。

## 6. 状态机、恢复和供应商未知执行

Root状态：QUEUED→RUNNING→READY；可进入PARTIAL、FAILED、EXPIRED、REVOKED、STALE。phase区分准备/素材/组织/检查。PARTIAL不是成功终态，文档必须标缺口，若尚不能可靠整合则只展示已有章节及清单。不能将缺口左右内容拼成无提示的完整推导。重试仅重新激活允许的缺口及依赖它的合成节点；新generation原子发布后替换预览。重启扫描持久Root和依赖，复用有digest证明的完成结果，不依赖浏览器续接。

外部调用ledger状态PREPARED→DISPATCHING→RESULT_STAGED→COMMITTED；DISPATCHING在请求发送前落库。调用超时、进程死亡或响应丢失后无法确认是否执行，标UNKNOWN，不自动重发。供应商若提供任务ID/幂等协议，先查询或用同operation key协调；没有可查询ID/幂等保证时，任务显式进入需重试状态，告知用户本次未完成，重新发起会产生新的处理尝试。必须先保留既有最坏成本占用，再为新尝试预留预算；不能释放UNKNOWN成本假装没消费。网络失败“确定未派发”才可自动重试。先记录intent的崩溃空窗可能根本没发送，但为避免重复计费仍保守UNKNOWN。

租约fence只保证唯一有效提交，不证明供应商恰好调用一次。UNKNOWN工作不得被现有claim逻辑重领后直接派发：需在通用内容worker增加ledger派发屏障，或notes专用worker在模型前检查ledger；旧worker必须按专用stageVersion隔离。心跳失效后旧调用可能仍在运行，占用槽位至真实退出；跨进程供应商调用不明时保留分布式inflight reservation并进入协调，不能只依赖本地busy。重试次数、deadline和预算全部覆盖旧未知调用。

## 7. 音画材料和全片覆盖

先根据权威媒体时长生成无缝owned区间，首轮建议每段60秒（低于当前ASR120秒/4MB上限），每侧最多5秒上下文重叠，尾片截至时长。这些为PoC参数，需比较句子截断、内存和费用。材料保留真实dependency范围，owned区间用于去重，不通过裁剪CLIP级转写伪造精确句子。转写重叠可能重复，合成保留来源并检测重复，不随意删除否定或补全半句话。

每段独立获取音轨及选帧；静音必须通过成功的媒体读取/检测得到NO_SPEECH或NO_AUDIO_TRACK，调用失败不是静音。无对白仍要求视觉材料。黑屏/纯音频允许明确“无可用画面”记录，不能把提取失败当黑屏。ASR默认保留当前百炼适配，不迁移服务。视觉任务复用供应商协议适配，使用全片任务独立预算和提示词，不套用当前问答30/90秒规则。

视觉首轮采用规则化时间覆盖+补充变化点+边界帧；在固定采样预算下登记实际sampledAtMs和盲区。未知类型不自动减到少量帧，人物动作/屏幕演示/手写公式需要特别评测；不将全图相似或OCR一致直接判为无变化。首版不依赖全量OCR模型，关键公式/代码不清时做有限补帧；仍不清就标识缺失，必要时阻止READY。关键截图P1但视觉理解P0，二者不混淆。

每单位材料包含range、modalityStatus、rawRef/digest、timePrecision、visualObservations、transcript、claims、speakerConfidence、uncertainties。语音原文不被模型纠错覆盖；视觉观察与推断分开。无明确身份的说话人用“发言者A”，不猜人名。

覆盖manifest验证：冻结owned区间并集严格为[0,D)，不存在gap/overflow；每区间所需模态成功或有可验证的“不适用”记录；全部依赖同媒体版本/授权域/策略，引用落在真实依赖范围内。UI建议文案“已处理完整视频；画面基于采样分析”，不称逐帧完整理解。材料齐全是必要条件，内容覆盖还需章节/关键事件质检；不能仅由成功任务数决定READY。

## 8. 文档合成和校验

分片事实先保留具体信息，不能只保存一句摘要。全局提纲读取全部分片的紧凑主题记录，正文按章节读取相应原始材料与相邻上下文；跨章节共用定义/人物表附来源，不把模型推断升级为权威事实。长视频采用有界树状分层整合，每层保留来源索引和未解决项；拒绝静默截断上下文。总纲生成/章节生成/最终概览固定DAG和调用上限，预算耗尽降为PARTIAL或FAILED，不无限Agent循环。

文档Schema建议：header（videoId/version/duration/language）；overview；keyPoints；sections[{id,title,range,blocks,citations,uncertainties}]；conclusions（可空）；coverage；provenance。blocks为paragraph/list/table/math/code/figure的受控union，文本与公式分字段，不接受任意HTML。引用由citationId映射到服务器验证的证据范围与精度；模型不得提供任意URL。章节目录由sections生成，不再另让模型生成一份可能漂移的目录。

确定性检查：schema/大小、source digest、范围、顺序、证据存在、文档所有引用有效、覆盖及预算、公式语法、无脚本/危险URL、状态和权限；语法合法不代表公式正确。语义检查：主要主题及例题遗漏、观点归属、否定和条件、数字公式与来源冲突、无依据外推、跨段衔接。最多一次有界修复，保留原检查/修复记录；仍有重大问题则PARTIAL/FAILED，不发布为完整。模型质检不是正确性证明，发布前仍需人工基线集验收。

## 9. 权限、版本和交付

处理授权来自现有业务桥接，明确用途FULL_VIDEO_NOTES及[0,D)。每次准入、领取、供应商派发、提交、发布和读取/复制均实时复验；后台用短期可续处理grant，不持久化用户JWT。续期重新验证原请求主体资格，不能服务账号自动续成永久权限。授权服务不可用时失败关闭/等待，不默认放行。

续期是新增契约，不假定现有Service已支持：Root deadline与grant有效期独立；每个work当前attempt deadline=min(rootDeadline,grantExpiry)，符合现有enqueue条件。协调器在派发前取得覆盖本attempt最大时长的有效grant，否则不发送。队列中等待将到期的grant，可新增受控renewQueued事务：仅QUEUED/RETRY_WAIT、无dispatch intent、CAS版本/旧grantId匹配，重新核对同asset与root主体后更新grant和attempt deadline，Root上限不变。RUNNING不能原位换grant：临近到期取消并阻止新派发，已派发结果若过期不能提交；等待真实调用退出后按ledger协调。FAILED/EXPIRED通过现有requeue新grant并递增fence，但UNKNOWN必须先协调，不能自动重发。未完成该持久续期/过期故障验证前，单work只在原grant内运行，到期则暂停等待新的明确尝试，不能宣称整片任务可无缝续期。

媒体版本必须由受约束播放/读取描述绑定ETag或对象versionId；若实际媒体读取不支持版本条件，禁止仅靠前后查metadata声称不可变，须先修通。sourceVersion/时长/授权域/epoch变化→STALE/REVOKED，旧worker无权提交。读文档和每张私有图都走实时鉴权代理，不发长寿命公共链接；浏览器缓存private/no-store并在账号切换清空。已复制到用户本地的内容无法撤回，应与线上访问撤权语义区分。

首版root和成品均按user隔离，不扩大至跨账号共享。以后共享只能针对业务授予的公共授权域，以素材身份及完整来源去复用，并在消费时重新鉴权。删除/保留期/撤权域变更进入清理队列，先阻断访问后异步清理，对象引用计数防止删除其他合法依赖。建议保留期随视频/用户删除策略，不另立无限存储。

## 10. 前端、预算和部署

已核对`front/src/agent/answer-renderer.mjs`关闭raw HTML、KaTeX trust=false及DOMPurify清洗，但超过64000字符回退pre且禁止img。只复用其中公式安全配置/转义原语与测试，不将完整长文拼接成单次v-html；NotesView按受控blocks组件分页或分章节渲染，表格/代码限制大小，截图使用鉴权组件而不是放宽Markdown图片URL。总文档和单block大小分别设限，超限不静默截断为完整文档。

新增`front/src/components/agent/VideoNotesView.vue`及对应API模块（建议路径），视频页入口与聊天解耦。桌面目录+正文，手机单列折叠目录。轮询返回真实phase和完成单元数；离开不取消；视频/账号切换立即解绑订阅和清空旧内容。时间跳转只针对匹配版本播放器，保持播放/暂停状态。复制由schema生成纯文本/Markdown并附站内来源；不新增模型调用。首版下载P1不阻挡P0，截图P1与版权/权限走既有媒体体系。下载时重新授权，PDF/HTML不因渲染差异遗漏公式。

预算在准入估算并数据库预留：N分片，C≈N×(ASR+视觉)+提纲+章节数+概览+检查+修复上限；补帧/重试计入同一Root，实际模型token、处理秒数、费用估计分别记录，不能只记文本Token。供应商单价属于部署配置、留版本，不写死或声称精确账单。任务/用户/全站有时长、字节、调用、token、预算、并发和deadline上限；UNKNOWN计最坏预留。每次dispatch原子扣可用预算；不能各子任务重复拿完整Root预算。ModelBudget本地实例不足以实现跨worker账本，需新增Root reservation实现复用其接口语义。

此前观察服务器4核约4GB、swap接近耗尽、磁盘98%，Agent容器约640MB限制；这些是瞬时记录而非容量保证。上线前必须清理/扩容及实测。首轮独立worker全局并发1、用户活跃任务1为建议，接入前台保留容量；流式抽取短片，不加载全片base64，多媒体tmp文件限制与finally清理/重启清扫；不在生产装OCR/向量数据库。优先使用已有远程模型与对象存储，不引入Kafka作为新队列。磁盘/内存水位达到阈值拒绝新任务，而非处理到中途耗尽。

## 11. Trace、验收与迭代

Root trace关联jobId、sourceVersion hash、plan/policy digest；子任务span关联work/fence/attempt/providerRequestId、范围、采样时间、缓存命中、租约、排队/提取/ASR/视觉/合成/检查耗时、实际预算和UNKNOWN。后台进程重启用span link延续因果，不复用已结束上下文；不记录key/JWT/签名URL或默认全文敏感材料。Trace非状态权威。

验收：PRD至少12条人工视频建立全片必保留要点/事件/公式/步骤/人物归属清单，独立标注再测试，增加画面主导、静音、混合章节、快速转场、遮挡、尾片、长视频和跨段例题；测每类关键内容召回/错误并保留失败样本，不能以总体均分掩盖重大错误。全部P0功能场景通过；虚构重要事实/错公式/错归属/遗漏核心章节任何一项不通过。记录冷生成P50/P90及分钟视频成本、内存峰值、缓存打开时间，不凭一例承诺秒数。

故障测试必须包括：并发POST唯一Root、进程在调用前后/结果存储后/事务提交前后崩溃、提交响应未知、租约换主旧结果、UNKNOWN不重发、预算并发超扣、权限撤销/服务不可用、对象替换、跨租户/用户访问、补齐缺口及合成失效、UI切账号、无声/ASR失败区分、对象孤儿清理、未响应取消不释放资源。新表/ledger/前台交付抽取需独立实现审查。

阶段A：冻结合同和3类代表素材，确认时长/容量与模态质量；阶段B：持久任务+材料manifest+ledger故障测试；阶段C：合成/阅读/引用/复制及真实12条验收；阶段D：小流量上线，观察质量、完成率、成本、UNKNOWN与队列，再做P1截图/下载。每阶段只报告实际证据，不把设计通过当发布通过。

迁移先新表/兼容reader，worker与入口默认关闭；测试后先启用worker再小范围入口。回滚关新任务准入，已接任务有界完成或安全暂停，保留ledger和已有可读产物；不能直接删除表或把UNKNOWN重新派发。旧“讲懂这里”和index不受该开关影响。
